# Мапа Business Manager — дорожня карта

Мета: 100%-точна копія реального інтерфейсу (справжні скріншоти + невидимі клікабельні
зони), не намальований макет. Метод і формат кожного розділу — у `content/business-manager-map/README.md`.

Позначки: ✅ готово (скріни + hotspot-екран у застосунку) · 🟡 частково (є текстова мапа
або скріни, ще не hotspot) · ⬜ не почато.

## Велике бачення (рішення автора, 2026-09-30)
Кінцева мета — не набір окремих завдань, а **повний навігаційний граф** кабінету: кожна
кнопка на кожному екрані записана з (а) точним текстом кнопки, (б) координатами, (в) куди
вона веде (`leadsTo` → id іншого `BmScreen`). Звідси випливає кілька шарів, які будуються
поверх того самого масиву даних `BmScreen[]`, без переробки формату:

1. **Тренажер-завдання** (є зараз): 2-4 hotspot з kind `'task'`, один правильний, з feedback.
2. **Повна карта шляхів**: усі кнопки екрана як hotspot з kind `'nav'` (label + leadsTo),
   навіть ті, що не входять у конкретне завдання. Знімаємо їх одночасно з завданнями —
   дешевше зробити зараз, ніж переходити по кожному екрану вдруге.
3. **Довідка/тур по кабінету**: розбити навчання орієнтуванню по кабінету на розділи, з
   можливістю «показати шлях до фічі X» — веде гравця по ланцюжку `leadsTo` від поточного
   екрана до потрібного.
4. **«Секретики» з досвіду й форумів**: короткі підказки-підводні камені під конкретними
   екранами карти (не з офіційної документації, а практичний досвід). Перший безкоштовно,
   решта — за окрему підписку/донат. Контент пишеться окремо, коли карта достатньо готова.

Порядок 2-4 підтверджується по ходу — можливо частину зробимо одночасно з 1, а не строго
послідовно.

## Практичне правило для екранів зі списками (кампанії/адсети)
Реальні назви товарів/кампаній **не показуємо** — замінюємо на загальні назви категорії
товару. Дати, бюджети, статуси, налаштування — лишаємо як є. Назви кампанії та її адсетів
мають лишатися узгодженими одна з одною (та сама категорія для кампанії і для її адсетів),
щоб студент бачив приклад **послідовного нейминга**, а не хаос — це частина навчальної мети.

**Метод, який реально працює (тестовано на Sergey G4, 2026-09-30):** заміна тексту напряму
в DOM (`node.nodeValue = ...`) **ламає React-віртуалізовані таблиці** цього кабінету —
рядки після цього дублюються/з'їжджають при наступному ререндері. Робочий спосіб:
1. Знімаємо скріншот з РЕАЛЬНИМИ назвами (тільки акаунт заблюрений через `style.filter`,
   це safe — не мутує текст/дітей).
2. Заміну робимо **локально на самому PNG** через sharp (`scripts/bm-tools/relabel.cjs`):
   прямокутник + SVG-текст поверх. **Колір прямокутника береться семплом пікселя з самого
   скріншота** (з порожнього місця в тому ж рядку), не hardcoded білий — інакше виглядає
   як заліплено в Paint. З урахуванням зебра-смуг (парні/непарні рядки трохи різний відтінок)
   семпл робиться **окремо для кожного рядка**.
3. Координати рядків через `getBoundingClientRect()` **не збігаються 1:1** зі скріншот-пікселями
   навіть коли `window.innerWidth` дорівнює ширині скріншота — і сам зсув нестабільний між
   викликами (в одному тесті знадобилось +26px по Y, в іншому — інше). Тому: міряй координати,
   одразу роби скріншот (без пауз між ними), і бери **великий прямокутник на всю висоту рядка**
   (~46px, а не щільно по тексту). Пробний рендер → подивитись на картинку → підправити цифри.
4. Ширину прямокутника підбирай **індивідуально по рядку** (не одне число на всі): замало —
   лишається «примара» старого тексту праворуч; забагато — заліз у сусідню колонку (Delivery).
   Орієнтир: права межа прямокутника ≈ на 10-15px раніше початку наступної колонки.

## Порядок роботи
1. Обираємо один розділ зі статусом ⬜/🟡.
2. Живий акаунт → Claude in Chrome → скріни кожного стану екрана (порожній/заповнений/під час дії), затираємо назву/ID акаунта і будь-які особисті дані.
3. Скріни → `app-mvp/assets/bm/<розділ>/*.png`.
4. Дані hotspot-ів (координати, підказки, правильна дія) → `app-mvp/src/data/bm/<розділ>.ts`.
5. Рендер тим самим компонентом `ScreenHotspot` (app-mvp/src/components/ScreenHotspot.tsx).
6. Позначаємо ✅ у цій таблиці.
