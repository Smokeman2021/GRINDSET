# 007 · Перевірка безпеки кандидата b28

**SHA кандидата:** `9b45b00` (збірка b28). **Діапазон:** зміни після b27 — `2db18eb..9b45b00`.
**Засіб:** `security-review`, прийнятий власником замість `claude-security`. Субагенти не використовувались (заборона власника): аналіз і відсів хибних спрацювань — в одній сесії.

## Знахідки

| # | Важливість | Що | Виправлення |
|---|---|---|---|
| 1 | середня | 0009 додавав захист від старої збірки в `save_progress` заміною рядка. Якщо визначення на продакшні відрізнялось би від 0007, заміна тихо не відбулась би, і після скидання стара збірка в режимі legacy могла б повернути видалений прогрес | Міграція тепер зупиняється з помилкою `save_progress_patch_failed`, якщо перевірку не додано. Тест перевіряє, що в `save_progress` після 0009 є `progress_legacy_blocked` |
| 2 | середня | SQL повного відкату містить дані тестерів (тексти відгуків) у лапках `$тег$`. Тег був випадковим, але не перевірявся на збіг із даними. Збіг дав би SQL-інʼєкцію при виконанні власником у SQL Editor (з правами `postgres`) | Тег — `grindset_backup_<uuid>`, повторно генерується, доки трапляється в даних. Тест із «шкідливим» відгуком |
| 3 | середня (наявна на продакшні) | `revoke_user_sessions(uuid)` — EXECUTE для `authenticated` через типові права Supabase: тестер міг видалити сеанси будь-кого, знаючи `auth`-UUID (UUID клієнту не віддається) | Відкликано в 0007 (крок 2 вікна) і в 0009. Тести: репетиція (після 0007), `reset.test` «права». До вікна на продакшні лишається відкритим; закриється першим кроком зміни бази |

**Низька важливість (до відома):**
- **Архів** `progress_archive` зберігає повні знімки прогресу скинутих учёток (імʼя гравця, налаштування) без строку зберігання. Доступ — лише власнику. Після підтвердження, що відновлення не потрібне, архів можна очистити окремою командою.
- **Суми нагород від клієнта** (`save_progress_v2`) — рішення ТЗ-01, без змін (див. `report/006-security.md`).
- **Таблиці.** Права `TRUNCATE` / `TRIGGER` / `REFERENCES` і зайвий запис у службові таблиці на продакшні не експлуатуються (RLS, через API недоступно), але прибрані в 0009.
