# Викладка для баєрів: інструкція простою мовою

Це інструкція для тебе, не для програміста. Тут: що вписати у Vercel, як підняти Supabase, як видавати тестерам персональні коди, як уберегти Supabase від «засинання» і єдиний чеклист по порядку (розділ 7).

**Стан на 2026-10-18 (кроки 3.1 і 3.2 пакета 3, вхід за персональним кодом):** готові Vercel-конфіг, Supabase (таблиці, функція входу) і сам вхід. Вхід перевірено лише в режимі-імітації й автотестами, наскрізний тест із твоїм Supabase пройдемо разом.

**Як працює вхід.** Тестер вводить свій @нік і персональний код, який йому видав ти (виглядає як `K7M2-9QXP-4TDH`). Нік не секрет, секрет це код. Telegram, бот і домен для входу **не потрібні**. Код діє, поки ти його не замінив; один акаунт може бути активним лише на одному пристрої (новий вхід вилогінює старий).

Нічого не публікується само: ні акаунтів, ні сайту я не створював.

## 1. Що саме вписати у Vercel

> **Лише перед самим запуском тесту** (див. чеклист, розділ 7). Домен більше не потрібен для входу, тож пробний деплой тільки для того, щоб побачити застосунок у справжньому вигляді; посилання нікому не розсилай, доки не готовий запуск.

Коли у Vercel натискаєш «Add New → Project» і вибираєш репозиторій, у формі «Configure Project» вписуєш:

| Поле у Vercel | Що вписати |
|---|---|
| **Framework Preset** | `Other` |
| **Root Directory** | `app-mvp` (натисни Edit і вибери папку; без цього збірка не знайде застосунок) |
| **Build Command** | `npx expo export --platform web` (вмикай перемикач Override і впиши) |
| **Output Directory** | `dist` (теж Override) |
| **Install Command** | залиш типовий (`npm install`) |
| **Node.js Version** (Settings → General) | `22.x` |

Решту (редирект усіх адрес на головну сторінку, заборону індексації, кешування) уже зроблено у файлі `app-mvp/vercel.json`, нічого вписувати не треба.

Тариф: **Hobby** (безкоштовно). На Hobby діє умова Vercel про особисте некомерційне використання; ти це знаєш і переходиш на Pro з релізом.

Яка гілка деплоїться: у Vercel → Settings → Git → **Production Branch** впиши `grindyk-real-renders` (тоді не треба зливати в `main`). Гілку `main` зливаєш лише ти.

Назву проєкту у Vercel дай нейтральну й не очевидну (не «grindset-test»): від неї залежить адреса `назва.vercel.app`.

## 2. Змінні середовища (Environment Variables) у Vercel

У Vercel: Settings → Environment Variables. Додаєш чотири змінні (усі для Production):

| Змінна | Що вписати | Де взяти |
|---|---|---|
| `EXPO_PUBLIC_CLOUD` | `supabase` | вмикає закритий вхід (без неї застосунок відкритий усім) |
| `EXPO_PUBLIC_SUPABASE_URL` | адреса проєкту, виглядає як `https://xxxx.supabase.co` | Supabase → Project Settings → API → Project URL |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | довгий ключ `anon public` | Supabase → Project Settings → API → `anon` `public` |
| `EXPO_PUBLIC_INCLUDE_RESTRICTED` | **`true`** (лише для цього тесту) | див. нижче |

> **Про `EXPO_PUBLIC_INCLUDE_RESTRICTED=true` (рішення автора 2026-10-18).** Для тесту потрібен чесний фідбек на повний курс, тому ризикові модулі лишаються в збірці. Мусиш знати, що це означає: тексти цих модулів лежать у файлі застосунку, який Vercel віддає **кожному, хто знає адресу, навіть без входу**. Тому: нікому не давай адресу поза списком баєрів; не клади її в чати й соцмережі; після тесту або вимкни деплой, або постав `false`. У повноцінній версії застосунку цього прапора не буде: ризикові модулі спершу перепишуть в інформаційну форму (що існує + ризики, без покрокового «як»). До речі, `false` вирізає ці тексти з файлу повністю (пакет 2, блок А), якщо захочеш обережніше.

**Важливо про секрети.**
- Ключ `anon public` публічний за задумом: доступ до даних обмежують правила в Supabase, а не секретність ключа.
- **Ніколи не вписуй у Vercel** ключ `service_role`. Він живе лише в Supabase (його підставляє сама функція входу).
- Без змінної `EXPO_PUBLIC_CLOUD` застосунок працює без входу (так він працює локально й у Expo Go).

## 3. Telegram (бот і домен)

Для входу **не потрібні**: ні бот, ні `/setdomain`. Нік у списку це просто імʼя, за яким тебе знаходять (краще брати нік у Telegram, щоб було зрозуміло, хто це). Варіант входу «код від бота» (з привʼязкою до Telegram-id) описаний у `docs/PLAN_LOGIN_CODE.md` і відкладений: повернемось до нього, якщо коди почнуть пересилати.

## 4. Supabase (безкоштовний план), покроково

Назви кнопок у панелі Supabase можуть трохи відрізнятись від написаного: шукай схожі за змістом.

**4.1. Розморозити проєкт.** Панель Supabase → твій проєкт → кнопка **Restore project** (відновлення займає кілька хвилин).

**4.2. Створити таблиці.** Ліве меню → **SQL Editor** → New query. Відкрий файл `supabase/migrations/0001_closed_test.sql` з репозиторію, скопіюй **весь** вміст, встав і натисни **Run** (має зʼявитись «Success»). Потім так само новий запит із **усім** вмістом `supabase/migrations/0002_invite_codes.sql`. Файли можна запускати повторно, нічого не зламається. Порядок важливий: спершу 0001, потім 0002.

**4.3. Додати себе адміном.** У кінці файла `0001_closed_test.sql` є закоментований блок «Перший адмін». У новому запиті встав його без `--` на початку рядків, заміни `твій_username` на свій нік **без @ і малими літерами** і натисни Run. Або в **Table Editor** → таблиця `allowed_users` → Insert row: `username`, `display_name`, `status` = `active`, `is_admin` = true.

**4.4. Видати собі код.** У SQL Editor виконай:
`select public.issue_invite('твій_username');`
У результаті буде код виду `K7M2-9QXP-4TDH`. **Він показується один раз** (у базі лишається лише хеш): скопіюй і збережи. Повторний виклик видасть новий код і скасує старий.

**4.5. Створити функцію входу.** Ліве меню → **Edge Functions** → Deploy a new function → **Via Editor**. Назва: `invite-login`. Видали весь код-приклад і встав весь вміст файла `supabase/functions/invite-login/index.ts`. Натисни Deploy. Потім відкрий налаштування цієї функції й **вимкни «Verify JWT»** (функцію викликають до входу, тож перевірка JWT їй не підходить; захищає персональний код і ліміт спроб). Секрети вписувати **не треба**: Supabase сам підставляє `SUPABASE_URL` і `SUPABASE_SERVICE_ROLE_KEY`.

**4.6. Де взяти адресу й ключ для Vercel.** Project Settings → API: **Project URL** і ключ **anon public** (не `service_role`!).

**4.7. Додати тестерів і видати їм коди.** Table Editor → `allowed_users` → Insert row: `username` (нік без @, малими літерами), `display_name`, `status` = `invited`. Потім для кожного: `select public.issue_invite('нік');` і надішли людині її код особисто (не в груповий чат). Пізніше це можна буде робити на екрані `/admin` у застосунку (крок 3.3).

**4.8. Заблокувати або замінити код.** Витік коду: виконай `select public.issue_invite('нік');`, старий код одразу перестає діяти, новий надішли людині. Вимкнути доступ повністю: у `allowed_users` постав `status` = `blocked`.

**4.9. Перевірка.** Відкрий застосунок (локально або на Vercel), введи нік і код, зайди. Потім відкрий із другого пристрою й зайди тим самим кодом: перший має показати «Вхід виконано з іншого пристрою». Хибний код 5 разів поспіль блокує нік на 15 хвилин.

Чого ще не перевіряли: функція входу й SQL **ще не запускались** на справжньому Supabase (є лише автотести логіки й імітація). Якщо на якомусь кроці вилізе помилка, скопіюй її текст і надішли мені. Місце, яке я передбачаю як найімовірніше джерело помилок: обмін одноразового посилання на сесію (`magiclink`; якщо Supabase відповість помилкою, змінимо на `email`).

## 5. Keep-alive: щоб безкоштовний Supabase не засинав

Що це: заготовка `ci/supabase-keepalive.yml` (після увімкнення вона працює як `.github/workflows/supabase-keepalive.yml`) кожні 3 дні надсилає в Supabase крихітний запит (читання одного рядка таблиці `keepalive`). Для Supabase це звичайна активність, тож «лічильник тижня» скидається.

Що зробити тобі:
1. **Увімкнути файл.** Мій git не має права створювати файли в `.github/workflows` (GitHub відхилив це), тому заготовка лежить у `ci/`. На сайті GitHub: репозиторій → Add file → Create new file → у назві впиши `.github/workflows/supabase-keepalive.yml` → встав увесь вміст файла `ci/supabase-keepalive.yml` → Commit changes → вибери гілку **main**. Так файл одразу опиниться там, де за розкладом його запускає GitHub.
2. GitHub → репозиторій → Settings → Secrets and variables → Actions → New repository secret.
3. Додай два секрети: `SUPABASE_URL` (та сама адреса `https://xxxx.supabase.co`) і `SUPABASE_ANON_KEY` (ключ `anon public`).
4. Вкладка Actions → «Supabase keep-alive» → Run workflow: перевір, що запуск зелений.

**Відомі ризики (їх треба знати):**
1. **Умови Supabase.** Я не знайшов в офіційних умовах або документації Supabase ні дозволу, ні заборони на такі запити; сторінка тарифів лише каже, що Free-проєкти засинають після тижня неактивності й не визначає, що саме вважати активністю. Спільнота широко користується цим прийомом, але **офіційного підтвердження в мене нема**. Якщо Supabase колись це заборонить, повернемось до Pro.
2. **За розкладом файл запускається лише з головної гілки `main`.** Тому в пункті 1 вище файл створюється одразу в `main`. Поки його там нема, розклад не працює, і засинання треба стерегти руками (раз на кілька днів заходити в панель Supabase).
3. **Ненадійність розкладу.** GitHub інколи затримує або пропускає заплановані запуски. Якщо запит не пройде, GitHub надішле лист про помилку запуску: тоді відкрий Supabase і натисни Restore.
4. **Не рятує від паузи, що вже настала.** Запит лише запобігає засинанню; якщо проєкт заснув, його треба розбудити вручну.
5. Якщо буде ненадійно, повертаємось до Pro ($25 на місяць).

## 6. Відомі ризики викладки

| Ризик | Що це означає | Чим пом'якшено |
|---|---|---|
| **Бандл публічний** | Сторінку (файли застосунку) Vercel віддає будь-кому, хто знає адресу, навіть без входу. Хто вміє відкрити код сторінки, прочитає тексти уроків, **у тому числі ризикові модулі, бо в тесті `INCLUDE_RESTRICTED=true`** (рішення автора). Вхід за кодом закриває дані й функції, а не файл. | Водяний знак з @ніком (крок 3.3), заборона індексації, адресу не поширювати поза списком, після тесту вимкнути деплой або поставити `false`. Винесення контенту на сервер заплановано як фаза 2. |
| **Код можна переслати** | Персональний код не привʼязаний до Telegram-акаунта: баєр може віддати його іншому, і той зайде (але активним лишається лише один пристрій). | Водяний знак з ніком власника видасть витік; код замінюється за секунду (`issue_invite`); коди надсилати особисто. За потреби повернемось до входу через бота (`PLAN_LOGIN_CODE.md`). |
| Блокування нікі зловмисником | Хтось може 5 разів ввести хибний код і заблокувати нік тестера на 15 хв. | Ліміт спроб з однієї адреси (30 за 10 хв); блокування коротке й саме знімається. |
| Vercel Hobby | Тариф безкоштовний, але за умовами призначений для некомерційного використання. | Твоє рішення: Pro з релізом. |
| Free Supabase | Може заснути, є ліміти. | Keep-alive (розділ 5), далі Pro. |
| Прогрес нараховується на телефоні | Коїни й XP рахує застосунок, не сервер. | Достатньо для закритого тесту без оплат; серверне нарахування для повної версії. |
