# GRINDSET — ПЕРЕРОБКА дизайн-інтеграції (критично, 2026-11-02 вечір)

Контекст: `app-mvp` (Expo / React Native Web, TS, Zustand), живий Supabase, Vercel, Telegram Mini App. Попередня інтеграція арту **зроблена неправильно**: непрозорі картини засунуті в маленькі прямокутні рамки/плитки, а геройські місця лишилися зі старим 3D-clay. Виглядає дешевше, ніж задумано. Треба **перебрати подачу**. Арт правильний — подача ні.

**Не ламай:** invite-login (щойно перезадеплоєно), Telegram initData-вхід, RLS, блоки A–F, paywall off.

---

## 0. НОВІ АСЕТИ (вже додаються в репо)
- **`assets/art-v2/cutout/<sub>/<name>.png`** — **ПРОЗОРІ** фігури (фон вирізано): `grindik/` (пози, mood, idle, portrait), `archetypes/` (6), `presets/` (4), `npc/` (4), `wardrobe/` (луки). **Імена ті самі, що в `character/`**, лише прозорий фон. **Будь-яка фігура на UI береться ЗВІДСИ.**
- `assets/art-v2/worlds/locations/*.png`, `acts/*`, `splashes/*` — **повні painterly-сцени** («світ через раму», зі склом/підвіконням у кадрі). Це **фони на весь екран**, а не мініатюри.
- `assets/art-v2/fx/objects/*`, `ui/nav/*` — об'єкти/іконки (вже ізольовані).

## 1. ГОЛОВНЕ ПРАВИЛО — геть рамки-плитки
- **Фігура (Гріндик / аватар / архетип / NPC) = прозорий cutout, що «стоїть/висить» на UI** з м'якою тінню (`drop-shadow`). **Ніколи** не в прямокутній рамці з бордюром і не обрізана в квадраті.
- **Світ/локація = фон на весь екран** (`cover`) з віньєткою (темніше зверху під HUD і знизу під картку). **Не** маленька закруглена плитка.

## 2. ЕКРАН-СЦЕНА УРОКУ (головний, еталон — див. опис нижче)
Композит згори вниз:
1. **Фон:** `worlds/locations|splashes/<scene>.png` на весь екран, `object-fit:cover`, `object-position` на фокус сцени.
2. **Віньєтка:** `radial` затемнення країв + `linear` темний угорі (≈16%) і внизу (≈86%), щоб світлий арт читався і текст був видимий.
3. **Гріндик:** `cutout/grindik/<pose>.png`, **повний зріст збоку** (ліворуч), висота ≈60–68% екрана, `drop-shadow(0 18px 22px rgba(0,0,0,.55))`, може **виходити за край/ламати четверту стіну**.
4. **Ціль (objective-glow):** зелений неон `#36e27a` — м'який `radial` bloom + пульсуюча точка-пін на точці цілі в сцені (вхід/стіл/каса).
5. **Заголовок «у просторі»:** пігулка `Модуль X · урок Y` + великий заголовок, `text-shadow`.
6. **Картка завдання (низ):** **СВІТЛА тепла** панель (`#f7f1e4→#ece3d0`), **темний текст**, зелена CTA-кнопка. (Це лагодить конфлікт темний-фон/світлий-арт.)
7. **HUD (верх):** пігулки 🔥/⭐/🪙/⚡ на напівпрозорому темному блюрі.

## 3. КАРТА УРОКІВ (екран «Уроки»)
- Прибрати **старих clay-маскотів** → поставити `cutout/grindik/pose_cheer.png` та `pose_think.png` (прозорі), що «висять» збоку доріжки.
- Фон доріжки — **не чистий чорний**: або смуга painterly-світу з сильною віньєткою/блюром позаду вузлів, або хоча б теплий темний градієнт. Світлий арт на чистому `#000` виглядає бідно.

## 4. GRINDYKSAY (репліка)
- Портрет/поза Гріндика = **прозорий cutout, стоїть поряд із бульбашкою**, не обрізаний у прямокутнику. Бульбашка лишається, фігура «висить».

## 5. ПРОФІЛЬ
- Великий аватар = **cutout обраного пресета/архетипа** на м'якій радіально-зеленій «сцені» (як зараз зелене світіння), повний зріст, що висить — **не старий clay**.
- Картка «Мій персонаж» — теж cutout.

## 6. КОНСТРУКТОР ПЕРСОНАЖА — ВИПРАВИТИ БАГ (критично)
**Поточний баг:** тап по типу одразу його «застосовує»; а коли обрав **основу**, потім **стиль одягу** — весь прев'ю підміняється на «чувака зі стилю одягу». Це неправильно.
**Правильна модель:** персонаж = **ОСНОВА** (1 з 6 архетипів) **+ ОБРАЗ/ЛУК** (1 wardrobe-лук) — **дві незалежні вкладки вибору**:
- Тап по **луку** змінює тільки вибір луку і прев'ю. Тап по **основі** змінює тільки вибір основи. Один ряд **не стирає** вибір іншого.
- Вибір на тап = лише **підсвічування стану** (highlight), а не миттєвий коміт. Коміт — **тільки кнопкою «Зберегти образ»** (вона вже є). Обидва вибори (основа + лук) зберігаються в профіль.
- Прев'ю поки показує **картинку обраного луку** як результат (бо wardrobe-арт — це вже вдягнена повна фігура); основа тримає свій highlight окремо. Коли з'являться пошарові асети одягу — прев'ю стане справжнім композитом base+layer **без зміни UX пікерів** (закласти так архітектуру).
- «Готові образи» (пресети) — одним тапом ставлять готову комбінацію (теж через highlight-стан, не підміняючи інші ряди наосліп).

## 7. ТЕМА / КОНТРАСТ (темне vs світле)
Новий арт **світлий і теплий**. Правила:
- Сцена = фон-арт на весь екран + віньєтка. Картки поверх арту — **світлі теплі** (`#f7f1e4/#ece3d0`) з темним текстом; **темний напівпрозорий блюр лише для дрібних HUD-пігулок**.
- Не лишати світлу картину маленькою плиткою серед великого чорного простору.

## 8. CACHE-BUSTING (перший вхід показав старого Гріндика/квіз)
Telegram Mini App агресивно кешує. Додати **версію/хеш** до URL бандла й асетів, виставити коректні cache-headers, скидати service-worker/кеш на новій збірці — щоб тестери одразу бачили нову версію, а не стару з кешу.

## 9. ПОРЯДОК, ЩОБ ВІДГРУЗИТИ СЬОГОДНІ
1. **Глобально:** кожну фігуру → її `cutout`; кожен світ → фон на весь екран; картки → світлі теплі. (найбільший візуальний стрибок одразу)
2. Екран-сцена уроку (п.2).
3. Карта уроків + GrindykSay + аватар Профілю (cutout, п.3–5).
4. Фікс конструктора (п.6).
5. Cache-busting (п.8).
Паралакс/гіроскоп/погоду поки можна лишити як є — вони не блокують візуальну переробку.

## 10. Еталон (словами, бо артефакт ти не відкриєш)
Екран уроку «Кафе»: повноекранна painterly-сцена кафе (видно інтер'єр «через раму»), Гріндик-cutout у зеленому худі стоїть **на весь зріст зліва**, ламаючи край; зелений неон-пін на касі; зверху пігулка «Модуль 01 · урок 1.4» і заголовок «Кафе «Своя чашка»»; знизу **світла тепла** картка «Моделі оплати: CPA/CPL/CPS» + зелена кнопка «Увійти»; у шапці HUD-пігулки. Саме так має виглядати будь-який екран-сцена.
