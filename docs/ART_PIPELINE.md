# Арт v2: як підключений і як його міняти

Стиль В (painterly, «світ у щілині»). Вихідні PNG лежать у `app-mvp/assets/art-v2/` (≈118 МБ, лишаються еталоном). У застосунок їде стиснена копія `app-mvp/assets/art-v2-opt/` (WebP, ≈5 МБ) і згенерований маніфест `app-mvp/src/art/manifest.generated.ts`.

## Як замінити або додати арт (код міняти не треба)

1. Поклади файл у `art-v2/` з **тим самим іменем** (або новий за конвенцією нижче).
2. `cd app-mvp && npm run art:build` (скрипт `scripts/optimize-art.mjs`).
3. Закоміть `art-v2/`, `art-v2-opt/` і `src/art/manifest.generated.ts`.

Це стосується й LoRA-канону Гріндіка: файли `character/grindik/*` замінюються з тими самими іменами. Єдине, що може знадобитись: підправити кадрування круглих портретів-емоцій у `src/components/Grindyk.tsx` (центр обличчя `fx/fy`), якщо нові файли скадровані інакше.

Ключ у коді = шлях без розширення: `worlds/locations/cafe`, `character/grindik/pose_wave`. Доступ: `art(key)`, `artKeys(prefix)`, `hasArt(key)` у `src/art/index.ts`.

## Папки й що з ними робить код

| Папка | Використання |
|---|---|
| `cutout/grindik/` | **ПРОЗОРІ** пози й емоції Гріндіка: мапінг логічних поз у `src/data/poses.ts` (`POSE_ART`), круглі портрети в `Grindyk.tsx` (центр обличчя рахується автоматично) |
| `cutout/archetypes/` `presets/` `wardrobe/` | **ПРОЗОРІ** фігури: конструктор персонажа (`app/character.tsx`, `src/art/character.ts`), аватар у Профілі |
| `cutout/npc/` | Поки не використано (чекає сюжетних сцен) |
| `character/*` (непрозорі оригінали) | **Не потрапляють у збірку** (пропускаються в `art:build`) |
| `worlds/splashes/` `locations/` | Заставки рівнів (`src/art/levels.ts` → `LevelSplash`) |
| `worlds/acts/` `transport/` `posters/` | Підключені в маніфест, у екранах ще не використані |
| `worlds/weather/` | Лише референс для overlay-погоди (самі кадри в застосунку не показуються) |
| `fx/objects/` `ui/nav/` | У маніфесті; поточні іконки (`assets/icons`) лишаються, поки автор не схвалить заміну |

## Конвенції для майбутніх файлів

- **Шари персонажа:** `character/layers/<слот>/<id>.png`, слоти `hair, skin, top, bottom, shoes, outer, accessory`; прозорий PNG на тому ж канвасі, що й база (`archetypes/*`). Щойно файли зʼявляться, конструктор покаже їх у слоті й перейде на пошаровий рендер.
- **Шари сцени (паралакс):** `worlds/layers/<назва плити>/bg.png`, `mid.png`, `fg.png`, де `<назва плити>` це ім'я плити (напр. `cafe`). Усі три файли потрібні разом; тоді `sceneLayers()` сам переходить із цілісної плити на три шари.
- **Покадрова анімація:** `character/grindik/anim/<назва>_01.png`, `_02.png` …; `flipbookFrames('character/grindik/anim/<назва>_')` дає кадри, `<Flipbook>` їх програє.

## Рівні → локації (`src/art/levels.ts`)

Кожен із 10 модулів має локацію, ціль (де світиться зелений ореол), точку старту й позу Гріндіка. Координати це частки зображення (0..1). Для 4 заставок із намальованим Гріндіком (модулі 1, 3, 5, 10) координати цілей поставлено за картинкою; для решти (позначено `calibrate: true`) вони «на око» й чекають уточнення: достатньо змінити числа в цьому файлі. Заставка показується перед першим уроком модуля при першому проході.

## Правило подачі

- **Будь-яка фігура на UI береться з `cutout/*`** (прозорий фон) і стоїть на екрані з тінню, без рамки.
- **Світ (`worlds/*`) це фон на весь екран** (cover) з віньєткою, не плитка.

## Відомі обмеження арту

- Вирізки (`cutout/*`) обрізані по контуру фігури й мають різний розмір (не спільний канвас): пошаровий композит у майбутньому потребуватиме файлів на спільному канвасі.
- Пошарових файлів поки нема, тому конструктор працює на цілісних образах (fallback).
