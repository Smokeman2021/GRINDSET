# 008 · Автоматичний вхід через Telegram і повне вікно викладки (b29)

Погоджено власником 18.11.2026 після звіту 007 і обговорення з Codex. Виконує Claude Code одним вікном, без повторного погодження кроків.

## 1. Автоматичний вхід (зараз)
- Сценарій: запрошений тестер натискає кнопку в чинному боті Гріндіка → сервер перевіряє підписані дані Telegram (initData) → знаходить учітку за Telegram ID → застосунок відкривається без інвайт-коду.
- Людина без доступу бачить зрозуміле повідомлення.
- Стара учітка без Telegram ID: одноразова підтверджена привʼязка (правильний код + підпис Telegram). Збіг ніка сам по собі нічого не дає.
- Права адміністратора й список дозволених — без змін.
- Перевірити: перший і повторний вхід, телефон → Desktop, відмова для недійсних даних Telegram.
- Наступний вільний номер збірки (b29), остаточний SHA, повтор перевірок, перевірка безпеки зміненого входу.

## 2. Вікно (одне, повністю)
Резервна копія → перевірка відновлення → погоджені міграції, push, злиття й деплой → перевірка нової збірки → скидання прогресу → перевірка чистого старту. Порядок — за `report/004-release-window.md`, оновленим під b29.

## 3. Копія
Обовʼязкова до будь-якої зміни продакшн-бази. Справжня копія продакшна — приватно, поза Git (`C:\Users\murak\GRINDSET-backups\<дата>\`), відновлення перевірено на ізольованій базі (дані, структура, функції, права). Без «КОПІЯ ПРИДАТНА» база не змінюється. Дія в акаунті власника — конкретним кроком.

## 4. Службова учітка `preview_check`
Перевірка входу, проходження уроку, синхронізації й відгуку. Не бере участі в рейтингу (`allowed_users.is_service`, міграція 0010). Реальний Telegram-вхід не імітувати — описати дію власника.

## 5. Скидання
Усі поточні тестери, включно з власником. Явний список ID — у приватному звіті до запуску. Зберігаються учітки, привʼязки Telegram, права адміністратора, відгуки, помітки, події. `preview_check` — окремим рядком. Скидання — окремий крок після перевірки нової збірки; далі чистий старт і захист від повернення старого прогресу з іншого пристрою.

## 6. Аварійний відкат
Обмеження b24 прийнято. При відкаті — пауза навчання й повідомлення тестерам; відновлення з архіву — окреме рішення.

## 7. Повернення до власника
Лише: доступ до акаунта, невдала перевірка копії, проблема кандидата, конфігурація суттєво відрізняється від плану. Підсумок: SHA, активна збірка, міграції, скидання, перевірки входу й прогресу, місце приватної копії, відкриті пункти Telegram-чекліста, запити моніторингу на 2 дні й ознаки втручання.
